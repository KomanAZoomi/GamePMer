# GamePMer 内网 Web 首个 Demo 设计

## 1. 状态与目标

状态：已完成视觉确认，等待文档审阅后进入实施计划。

本阶段不迁移旧 WPF 应用，也不接入企微、飞书、Outlook、真实邮件、报价或结项流程。目标是交付一个可在内网浏览器打开、可用虚构示例数据完整演示“客户反馈导致重排”的 Web 工作台。

验收问题只有一个：游戏美术 PM 能否在同一工作台内看清反馈、排期影响、草案和确认后的动作，并在五分钟内完成一次重排。

## 2. 已确认决策

1. 首个目标形态是内网 Web 工作台。
2. 首页采用排期优先布局，不采用异常优先控制塔作为主页面。
3. 视觉基调采用“制作工作室”：暖灰背景、鼠尾草绿为主要操作色、琥珀色用于草案和客户反馈、克制红色仅用于风险。
4. 首个 Demo 覆盖 3D PBR 阶段：中模、高模、低模、烘焙、贴图、LOD；2D 项目仅作为示例数据展示。
5. 客户反馈由 PM 手工粘贴或录入为反馈批次；连接器后置。
6. 反馈处理在甘特图内完成：反馈生成草案，PM 可直接拖动草案条微调。
7. 高模等阶段延后时，系统按工作日生成后续阶段的建议顺延草案，但绝不自动写入正式排期。
8. PM 一次确认后写入所有选中的修订；原基准永久保留，且生成组长和艺术总监通知草稿。

## 3. Demo 业务范围

### 3.1 主路径

1. 打开“项目排期”。
2. 在资产树中选择 `P-3D-024 / MECH-01 机甲主角`。
3. 看见 PBR 阶段、基准条、当前条、客户验收节点、今天线和周末。
4. 打开或新建反馈批次，粘贴“高模肩甲比例需要调整，预计返修 2 个工作日”。
5. 系统将高模延后 2 个工作日，并为低模、烘焙、贴图生成橙色工作日顺延草案。
6. PM 在甘特图中拖动任一橙色草案条进行微调。
7. 右侧确认抽屉持续展示反馈原文、受影响阶段、原日期、新日期、修订原因、说明和通知对象。
8. PM 点击“确认 3 项排期修订”。
9. 当前条更新为已确认日期；基准条保留；修订记录与通知草稿出现在抽屉中。

### 3.2 不在本阶段

- 真实聊天、邮件和官方接口。
- 自动发送邮件、自动修改网络盘文件或自动更新排期。
- 多用户协同、权限、账号体系和服务端数据库。
- 报价、结项、IT 剪切备份和 BD 出账。
- 通用表格导入导出。

## 4. 示例数据是产品的一部分

Demo 首次打开必须加载以下虚构数据，不能出现空白页面。

| 项目 | 类型与状态 | 用途 |
|---|---|---|
| P-3D-024 机甲主角 | 3D PBR；高模客户反馈延期 | 主路径与重排演示 |
| P-2D-018 NPC 套装 | 草图、细化 50%、完成稿；客户等待 | 2D 阶段与客户等待状态 |
| P-3D-031 赛博场景 | 多资产正常进行 | 正常排期与密度展示 |

`MECH-01` 的阶段基准、当前计划、客户验收节点、反馈批次和修订前后日期均为预置数据。示例中至少应展示一项正常阶段、一项 T-1 风险、一项客户反馈延期和三项待确认草案。

## 5. 页面与信息层级

### 5.1 项目排期工作台

三栏布局：

1. 左栏：项目和资产树、搜索、状态摘要。用于定位资产，不承载排期编辑。
2. 中栏：主甘特图。包含月份/周/日日期轴、周末底色、今天线、阶段行、基准条、当前条、草案条、客户验收菱形节点和缩放控制。
3. 右栏：上下文抽屉。未选反馈时显示资产健康度；处理反馈时固定展示反馈内容、影响、修订理由、通知对象和确认动作。

桌面优先，最低可用宽度 1280px。窄屏仅提示使用桌面浏览器，不把复杂甘特图压缩成手机页面。

### 5.2 反馈与重排状态

| 元素 | 视觉语义 |
|---|---|
| 基准条 | 细灰条，只读 |
| 当前条 | 鼠尾草绿，正式当前计划 |
| 草案条 | 琥珀色描边与填充，可拖动，未确认 |
| 客户验收 | 琥珀色菱形节点 |
| 反馈标记 | 琥珀色标签，可打开反馈抽屉 |
| 团队延期 | 克制红色状态，不改变甘特条颜色 |
| 周末 | 暖灰底色 |
| 今天线 | 细红色虚线，仅作时间参照 |

### 5.3 重排交互规则

1. 反馈批次选择“影响高模并增加 2 个工作日”后，当前高模条显示新结束日期，低模、烘焙、贴图产生按工作日计算的草案条。
2. 草案条仅能沿日期轴按整工作日拖动；周末和公司休息日不能作为开始或结束日期。
3. 拖动草案条不会更新当前条，也不会生成通知。
4. 每次拖动立即更新右栏的旧日期、新日期、影响数量和通知预览。
5. 确认按钮在“至少一项草案有改动、修订原因非空”时可用。
6. 取消丢弃草案，不改变当前计划。
7. 确认后保留基准，更新当前计划，添加不可编辑的修订记录，并生成未发送的通知草稿。

## 6. 技术边界

首个 Demo 使用 React、TypeScript、Vite 和浏览器本地持久化实现。应用启动时从版本化的虚构种子数据初始化；用户确认重排后保存到浏览器本地存储，刷新页面仍可看到变更，并提供“恢复示例数据”入口。

前端采用可替换的 repository 接口：Demo 使用 `LocalDemoRepository`，后续内网服务端接入时替换为 API 实现，不让甘特组件直接依赖 localStorage。

甘特图先使用自研、受控的横向时间轴组件，不引入与业务状态强绑定的黑盒甘特库。阶段日期、工作日计算、草案和确认逻辑以纯函数实现并单元测试；拖拽用 Pointer Events 实现并提供键盘微调替代入口。

## 7. 验收门禁

视觉验收已确认的基线位于本次脑暴原型；实施期间每一个切片都必须提供截图或可访问页面，而不仅是测试结果。

首个 Demo 完成需要同时满足：

1. 默认看到三组虚构项目与可读的排期密度。
2. P-3D-024 主路径可在五分钟内从反馈走到确认重排。
3. 甘特图有真实日期轴、今天线、周末、基准/当前/草案和验收节点。
4. 草案拖动、取消、确认和刷新后的持久化均可演示。
5. 确认后可以看到修订记录和通知草稿，且不会真实发送任何内容。
6. 自动测试覆盖工作日顺延、草案不污染正式排期、取消、确认和种子数据初始化。
7. 人工验收必须基于预置数据完成，不能以空页面或单元测试通过替代。
