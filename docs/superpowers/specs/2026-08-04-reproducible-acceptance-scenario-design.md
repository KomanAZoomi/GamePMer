# 可复现完整验收场景与数据迁移设计

## 目标

让任何同事在任意浏览器首次打开 Demo 后，都能一键载入同一条可从报价追溯到归档的虚构业务案例；同时允许以受校验的 JSON 在浏览器之间备份和迁移当前 Demo 数据。

## 问题与边界

当前 Demo 使用浏览器 `localStorage` 保存数据。该存储按浏览器配置和来源隔离，因此在 Codex 内置浏览器中录入的数据不会出现在用户 Chrome 中；系统也尚未配置共享后端。

本切片不引入内网 API、数据库、身份认证、多人协作或真实企业连接器。所有案例、人员、邮件地址与路径均为虚构、脱敏演示信息。

## 选择的方案

采用“官方完整验收场景 + 整体替换式 JSON 导入导出”。

- 官方场景由源码构造，不依赖某个浏览器的现有状态。
- 导入仅在文件通过解析和结构校验后允许继续，并在确认后整体替换当前状态。
- 不提供合并导入，避免项目编号、报价修订、审计事件和关联 ID 产生冲突。
- 现有“恢复示例数据”继续恢复基础种子数据；完整验收场景是独立入口，用户可随时切回。

## 官方完整验收场景

官方场景使用以下虚构主线，并保留每一步的证据和可解释状态：

1. `CO-004`：BD 提交的 3D PBR 报价，完成总监报价、组长复核、报客户和客户接受。
2. `SKF_A_3D_B52`：PM 发开工通知后创建的正式项目，至少包含一个 3D PBR 资产，阶段为中模、高模、低模、烘焙、贴图和 LOD。
3. `F-018`：客户针对一个已提交阶段提出的范围内反馈；反馈盘路径、候选来源与反馈项目均可查。
4. 重排修订：客户反馈导致受影响资产的后续阶段整体顺延；基准、当前和实际日期都保留，未受影响资产不被连带修改。
5. 结项：资产交付、客户确认、IT 剪切备份回执、BD 出账通知和归档路径均已形成可追溯证据。

场景需要同时保留“已经发生的历史”以及能在项目、排期、反馈、文件、结项和分析页面看到的投影，而不是只生成一个名称相同的项目卡片。

## 数据模型与模块边界

新增独立的数据场景构造模块，返回合法的 `DemoState`，不让页面直接拼装领域对象。基础种子仍由 `createDemoState()` 提供；完整场景由独立工厂提供，并复用既有领域模型、枚举与数据校验。

新增纯函数的备份包编解码模块：

```ts
export interface DemoBackupPackage {
  format: 'gamepmer-demo-backup'
  schemaVersion: number
  exportedAt: string
  state: DemoState
}

export function exportDemoBackup(state: DemoState, exportedAt: string): DemoBackupPackage
export function importDemoBackup(raw: string): DemoState
```

`importDemoBackup` 在 JSON 无法解析、包格式错误、版本不匹配或 `DemoState` 缺少必需集合时抛出可展示的领域错误。失败时不调用 Repository 的 `save`，从而不污染正在使用的数据。

Repository 继续是存储唯一边界，增加一个接收已校验状态的替换方法。Workspace Store 使用它更新订阅者和持久化数据；页面不直接访问 `localStorage`。

## 页面交互

“设置中心 → 数据与运维”提供四个清晰动作：

| 动作 | 行为 | 风险控制 |
| --- | --- | --- |
| 恢复基础示例数据 | 替换为当前基础种子 | 按现有行为执行 |
| 载入完整验收场景 | 替换为 `CO-004` / `SKF_A_3D_B52` 场景 | 明确说明会覆盖当前数据，二次确认 |
| 导出当前数据 | 下载 JSON 备份包 | 不包含真实凭证；提示按内网规范保管 |
| 导入数据 | 选择 JSON，先解析、校验并展示数据摘要，再确认替换 | 无效文件不写入；确认前不改变状态 |

数据摘要至少展示项目、报价、反馈、结项和审计事件数量。导入按钮使用隐藏文件输入，仅接收 `.json`；解析失败时给出可操作错误提示。正式数据替换后停留在设置页，并显示成功反馈，便于用户判断本次操作已经生效。

## 不变量

- 导入、加载官方场景和恢复基础样本均为整体替换，不能与旧状态合并。
- 解析或校验失败不得覆盖任何已有业务数据。
- JSON 导出不包含 API Key、浏览器外部凭证或真实文件内容；现有 DemoState 本身也没有完整 Key 字段。
- 场景中的阶段、反馈重排、报价门禁和结项门禁必须继续遵守项目领域不变量。
- 所有按钮都必须产生实际的下载、载入、确认、错误或成功反馈；不能出现无响应的展示控件。

## 测试与验收

先为纯函数建立红绿测试，再做 Store 和页面测试。

1. 场景工厂生成 `SKF_A_3D_B52`、`CO-004`、`F-018`，并证明反馈修订只影响目标资产后续阶段、结项证据完整。
2. 导出包包含固定格式、当前 schema 版本和完整状态；同一状态经导出再导入后保持可用。
3. 非 JSON、错误格式、错误版本和缺少必需集合的备份包均被拒绝，旧 Repository 状态不变。
4. Workspace Store 能加载官方场景及已校验导入状态，并在刷新后仍从 Repository 读到替换后的数据。
5. 设置页面可触发场景载入、导出和“选择文件 → 校验摘要 → 确认替换”的交互；取消和失败均不改变现有数据。
6. 真实浏览器在 1280、1440 和 1920 宽度验证加载、导出、导入、确认与数据投影；完整质量门禁为 `npm.cmd test`、`npm.cmd run lint`、`npm.cmd run build` 和 `npm.cmd run test:e2e`。

## 非目标

- 不把浏览器本地数据伪装成多人共享或服务端持久化。
- 不实现 JSON 合并、冲突解决、云端同步、自动备份或真实对外发送。
- 不修改当前项目业务状态机、阶段模板或权限策略。
