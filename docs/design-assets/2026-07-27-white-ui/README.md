# 白色内网 Web 工作台 — 视觉基线资产（2026-07-27）

## 这批文件是什么

这是 GamePMer 内网 Web 工作台**唯一经过用户确认的 UI 规格来源**。

`docs/superpowers/specs/2026-07-27-intranet-web-workspace-redesign-design.md` 用文字定义业务、领域模型和状态机；
本目录用图定义布局、信息密度、组件形态和术语。两者是同一份设计的两个面，**实现时必须同时对照，不能只看文字**。

原始文件产自 `.superpowers/brainstorm/white-ui-architecture-20260727-v3/`，该目录被 `.gitignore` 忽略、
只存在于单台开发机、且配套预览服务会超时失效。2026-07-27 经用户授权复制到此处纳入版本控制，
避免重蹈 M1「只有文字规格、没有视觉基线」的覆辙（见 `docs/retrospectives/2026-07-16-m1-vibe-coding-retrospective.md` 根因一）。

## 已知缺口

**排期管理与团队档期页（设计说明 §6.2）没有原型和截图。** 它是七个核心页面中唯一只有文字规格的一个，
而它恰好承担「团队装不装得下」这一核心价值，且直接关联 M1 失败点第 3 条「录入排期和档期太过简单」。

实现该页面前必须先补一版静态原型交用户确认，不能直接从文字进入编码。

## 使用规则

1. **原型定结构，不定实现。** 忠实复刻布局、信息层级、密度和术语，但用真实的 React 组件、
   设计令牌和响应式布局实现，不允许把静态 HTML 整体硬编码进组件文件。
2. **原型里的数据是虚构示例，不是种子数据规格。** 正式种子数据以设计说明 §11 为准。
3. **修改视觉基线需要用户重新确认。** 本目录不随实现自由演进；若实现中发现原型有问题，
   先提出、确认后再更新此处文件，并在提交信息中说明变更原因。
4. 正文实现字号不小于 14px；状态不能只用颜色编码；1280 / 1440 / 1920 三档都要检查。
