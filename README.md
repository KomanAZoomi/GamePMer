# GamePMer

面向游戏美术 PM 的**公司内网 Web 工作台**。

当前交付两条可验收的纵向闭环：

1. **候选收件箱**：外部消息 → AI 识别 → PM 核验 → 确认后才生成正式记录
2. **反馈重排**：客户反馈 → 范围分流 → 排期重排 → PM 确认 → 修订与通知草稿
3. **报价与接项目**：BD 需求 → 需求入库 → 总监报价（含排期）→ 组长兼 BD 一次复核 →
   BD 报给客户 → 客户确认 → PM 发出开工通知，**这一刻才正式建项**
4. **结项与出账**：资产验收 → 最终包 → 客户确认 → IT 备份回执 → 通知 BD 出账 → 归档
5. **文件与归档**：按批次登记盘位路径 → 一键复制 → 结项直接取用（只登记路径，不搬文件）
6. **智能分析**：正式记录的投影 → 延期归因 → 逐阶段下钻（客户等待与团队延期分开，不下钻到个人）
7. **设置中心**：供应商预设 → 只填 API Key → 用途分档 → 发送前脱敏（Key 由服务端保管，前端只留后 4 位）

所有项目、客户、资产和消息均为虚构演示数据。工作台**不接入**真实邮件、企业微信、飞书或文件盘，
也不执行任何真实的对外操作——这是当前阶段的刻意边界，不是尚未接好的接口。

## 已实现的页面

| 页面 | 状态 | 说明 |
|---|---|---|
| 任务管理（首页） | 可用 | 待办由正式业务状态投影生成，每条都能追溯到项目、资产、阶段或反馈 |
| 项目总览与甘特 | 可用 | 按资产分组展开到每个可验收阶段，基准/当前/实际/等待客户四层日期同屏可比；阶段可逐步推进到客户验收 |
| 排期管理与团队档期 | 可用 | 跨项目组合排期、制作组周容量、节点清单、批量计划录入与冲突检查 |
| 反馈中心 | 可用 | 反馈拆成资产级项、范围分流、重排草案、确认事务与通知草稿 |
| 候选收件箱 | 可用 | 零审批导入、逐字段置信度、阻断说明、确认事务生成正式记录 |
| 报价与变更 | 可用 | 需求直接录入、六步审批链、版本化报价、总监录入、双角色合并复核、客户确认门禁、开工建项、只冻结受影响资产 |
| 结项中心 | 可用 | 五道串行证据门禁、正式邮件校验、出账资料自动汇总、退回与归档 |
| 文件与归档 | 可用 | 按批次登记六个盘位路径、编号逐段解析、一键复制、结项直接读同一份 |
| 智能分析 | 可用 | 交付表现、延期四类归因、制作组负载、报价统计，每个数字能下钻到阶段 |
| 设置中心 | 可用 | 六个 LLM 预设、用途→模型分档、连接器审批门槛与替代路径、成员角色、业务规则、运维与已知限制 |

顶栏全局搜索（`e2e/search.spec.ts`）覆盖项目 / 资产 / 阶段 / 反馈 / 候选 / 报价 / 结项 / 路径八类，
按编号、名称、客户原文和路径匹配，编号大小写不敏感；`↑` `↓` 选、`Enter` 打开、`Esc` 关。
每条结果跳过去之后会**选中那条记录**——只切模块不选中等于让人重找一遍。

## 五分钟演示脚本

从「恢复示例数据」开始，这条路径有 E2E 用例逐步守着（`e2e/demo-script.spec.ts`）：

1. 首页看到 4 个项目、9 个资产、32 个阶段，以及 `P-3D-024` 的三条待分流客户反馈
2. 点开任一反馈，右侧显示原始邮件与批注截图路径、AI 判断依据（标明**建议未执行**）
3. 项目甘特里 `MECH-01` 六个 PBR 阶段各自成行，周末与公司休息日有底纹，今天线在 7/27
4. 排期管理看 3D 角色 A 组本周 `7 / 7.5` 人天；8/3 当周因 8/5 是休息日，可用人天降到 6
5. 反馈中心把「缩小肩甲比例」判为范围内 → 生成草案：受影响阶段顺延，LOD 跨过休息日排到 8/10
6. 微调草案，后续阶段自动顺延；甘特上草案是独立的斜纹层
7. **取消草案 → 正式计划零变化**
8. 重新生成并确认 → 写入修订 v1、基准保留、生成两封**未发出**通知草稿
9. 刷新浏览器，修订仍在
10. 把另一项判为范围外 → 创建变更单 `CQ-004`，只冻结受影响资产
11. 「恢复示例数据」回到相同初始状态

候选收件箱另有一条闭环（`e2e/inbox.spec.ts`）：

1. 打开候选收件箱看到 10 条候选，覆盖客户反馈 / 阶段完成 / 报价需求 / IT 回执四种类型
2. 每个字段各自带置信度和原文片段——不是一个笼统的百分比
3. 「需补全」里那条缺关联资产的：确认键禁用，右侧写明**缺哪个字段**
4. OCR 那条把 `0` 认成了 `O`，项目号置信度 42%，有值也照样阻断
5. 报价需求**只问客户和批次编号**，不问关联资产和制作阶段——BD 需求进来时项目还不存在，
   逼 PM 填后面的事只会让人填出一个假项目号。批次编号置信度 55%，得 PM 亲自过目；
   核验之后确认 → 建出报价案件，停在「总监报价中」且**没有任何报价版本**——
   确认候选只是承认「这是一条真需求」，人天和金额得总监自己填
6. 补上关联资产 → 字段标记「PM 填写」→ 确认键解禁
7. 确认 → 生成反馈批次 `F-018`，右侧能一路点到反馈中心
8. **忽略候选不改任何正式数据**，而且能退回待确认
9. 粘贴一段带 `【P-3D-031】PROP-02` 的文本 → 自动提取项目、资产、阶段
10. 贴一段没有项目号的文本 → 字段留空并阻断，**不编造项目号**
11. 同一段原文导入两次 → 自动判重，待确认数量不变
12. IT 回执那条确认 → 直接完成 `AUR_A_3D_B11` 的「IT 备份」门禁并带上邮件证据，
    接着能去结项中心通知 BD 出账。**串行门禁不因为证据来自收件箱就松**：
    前置没走完照样阻断，理由用结项层的原话

报价与接项目的第三条闭环（`e2e/quotation.spec.ts`）。完整链路六步：

```
BD 需求 → 总监报价 → 组长/BD 复核 → BD 报给客户 → 客户确认 → PM 发开工通知（建项）
```

三条容易被合并、合并了就再也拆不回来的分界：

- **复核通过 ≠ 已报给客户。** 组长/BD 内部认了，还没发出去。
- **已报给客户 ≠ 客户接受。** 中间这段等待是客户占用的，单独一个状态、单独一个指标。
- **客户接受 ≠ 已开工。** 首次报价要到这一步才真正建项目、发开工通知。

「审批链画几步，实际就得走几步」有测试绑着：链上六个节点与六次真实点击一一对应。

需求可以从收件箱确认进来，也可以由 PM 在这一页**直接录**——BD 当面说一句、电话里谈定的，
不该非得先伪造一封邮件。两条路进的是同一个 `createQuoteCase`，不允许各拼各的案件。
首次报价只问客户和**提议的**批次编号；追加报价改问挂哪个项目、冻哪些资产，客户从项目上取。



1. `CQ-004` 追加报价展开到每个阶段，各有人天、单价和节点——不是一个总金额
2. 待复核清单里 `CQ-004` **只有一条**，但「组长」「BD」两个角色都写出来，并标注「合并为 1 次确认」
3. 复核通过 → 甘特上 `MECH-01` 烘焙仍标「等待变更报价」：**批准不等于开工**
4. 发出变更开工邮件（人工声明）→ 资产解冻、排期按报价单更新、基准不动
5. 未受影响的 `MECH-02` 从头到尾没被这次变更动过
6. 应结汇总 = 首次报价 `Q-021` ¥42,000 + 追加 `CQ-004` ¥9,000，原报价版本没被改写
7. `Q-029` 客户已确认但项目**还不存在**——点「我已发出正式开工邮件」的那一刻，
   项目、资产、阶段按报价单一次性建出来，报价节点同时成为基准排期。
   新项目**不产生排期修订**：修订记的是「相对基准改了什么」，而新项目的基准就是这份报价单
8. `Q-030` 还在「总监报价中」→ 用「录入总监报价」按阶段模板生成行、填人天与节点 → 提交进入待复核
9. 「退回总监修改」不是死胡同：以上一版为底稿重新提交，生成 v2 且 v1 原样留档

结项与出账的第四条闭环（`e2e/closeout.spec.ts`）：

1. `P-3D-011` 五道门禁的状态一眼可见：01~03 已完成、04 当前门槛、05 前置未完成
2. 点被挡住的「通知 BD 出账」→ 只看到原因，**没有可点的完成按钮**
3. `P-3D-024` 还在制作 → 卡在第一道，并说清「还差 N 个阶段」；这一步**不给手工打勾的入口**
4. 用聊天截图当 IT 备份证据 → 被拒绝，并说明只认正式邮件
5. 换成正式邮件回执 → 解锁出账，右侧资料包从「缺 IT 回执」变「资料齐全」
6. 通知 BD → 生成带金额与路径的**未发出**草稿
7. 收到出账回执后**独立**归档；归档之后案件只读
8. 退回「总监整理最终包」→ 它后面三道门禁一并作废

文件与归档的第五条闭环（`e2e/files.spec.ts`）：

1. 路径**只挂批次，不挂阶段**——一个批次几十个资产，逐个登记这张表就没法看
2. 批次编号 `NST_A_3D_B24` 拆成客户 / 项目 / 类型 / 批次四段分色显示
3. 六个盘位（反馈 / 制作 / 提交 / 最终包 / 归档 / 参考）都列出来，没登记的也占一行
4. 手工填写路径并保存；「按约定填入」只是**建议**，不点保存不生效
5. 路径不合法（不是 UNC 或盘符开头）时保存被阻断，并说清怎么填
6. **一键跳转 = 一键复制**：浏览器不允许网页直接打开 `\服务器\共享`，界面写明原因而不是给个打不开的链接
7. 删除登记只删索引，**盘上的文件不受任何影响**
8. 还没建项、只在报价里出现的批次也能先把盘占好
9. 改归档路径后到结项中心看——**同一份数据，不是两套**

智能分析的第六条闭环（`e2e/analytics.spec.ts`）：

1. 每个数字都是正式记录的投影——去候选收件箱确认一条阶段完成，回来指标就变了
2. **客户等待与团队延期永远是两个数**：`RELAY-01 / 高模` 既有 2 天团队延期、又有 1 天客户等待，
   两者互不相消。制作延期发生在提交客户之前，客户还没看到东西，不可能是客户造成的
3. 归因四类各一行并说明各自是什么，逐阶段能下钻到是哪个阶段、归到哪一类
4. 四个页签都是真视图（交付表现 / 延期归因 / 产能与负载 / 报价与变更），不是摆设
5. **四个页签下都不出现任何制作人员姓名**——有专门的 E2E 逐个页签扫一遍
6. 人天偏差带样本数，样本少于 2 的不作为结论依据
7. AI 洞察分两类，行为不一样：
   - **卡点型**（几条反馈没分流、几件报价卡在复核）盯的是当下还卡着的事实，
     办完了这张卡**自己就消失**，所以不给处置按钮——给了会让人以为点一下就算办了。
     有 E2E 去反馈中心把三条判完，回来看那张卡确实没了。
   - **结论型**（某阶段实际比预估多 50%，建议调报价模板）是决策建议，不会自己消失，
     可以「采纳」或「暂不采纳」；**暂不采纳必须写理由**，否则半年后同一条结论
     原样冒出来，没人记得上次为什么否了。改主意保留全历史，界面显示最新一次。
8. 「仅建议 · 工作台不代做」**不是一个会翻转的状态，是一条承诺**——
   即使你照着建议做完了它也不变。会变的是上面那条处置，两者刻意分开
9. 每条洞察都写「依据：N 条记录」

设置中心的第七条闭环（`e2e/settings.spec.ts`）：

1. 六个供应商预设的地址与模型都预填好，用户只需要填 API Key
2. 填进去一个真 Key 再提交 → **直接翻 `localStorage` 搜，搜不到**；只留 `••••6789` 后 4 位
3. Key 输入框是 password 类型；格式不对时提交按钮禁用并说明哪里不对
4. 右侧「三条不让步的约束」逐条写清 Key 去哪、前端留什么、谁能读——**没有一个角色能读回完整 Key**
5. 用途分五档：提取和解析走便宜档（haiku），分流与起草走中档（sonnet），每档标出单价
6. 连接器如实标注审批门槛：四条零审批已接入，公司邮箱本人可授权，企微与飞书需企业管理员——
   **每条未接入的都给出替代路径**，不是写个「敬请期待」
7. 业务规则里的批次编号规范与解析器同源（`domain/batchCode.ts`），改这里等于改业务
8. 运维页逐条摆出已知限制和当前数据规模，不做自我表扬

## 几条不会让步的规则

这些规则都有测试守着，不是文档里的口号：

- **基准不可覆盖。** 所有修订只动当前计划，基准日期从头到尾没被写过。
- **草案不碰正式数据。** 生成、微调、预览全程不改 `StagePlan`，取消就是把草案丢掉。
- **确认是原子操作。** 有阻断时整体拒绝，绝不出现「部分阶段已改、部分没改」。
- **工作台不发信。** 通知只到草稿；真实发送由 PM 在 Outlook 或企微完成，回来标记。
  标记记录的是人工声明，不是系统投递回执。
- **AI 只建议。** 范围判定、排期修改、通知发送都要 PM 动手，界面上写明「建议未执行」。
- **容量按全量算。** 筛选只决定显示哪几行，不影响制作组档期数字——
  否则筛掉几个项目就会显示出不存在的空闲。
- **不留假控件。** 每个按钮要么真做事，要么禁用并说明在哪个切片交付。
- **候选不是正式记录。** 确认之前，项目、排期、反馈和结项的数据一个字节都不会变。
- **识别不出来就留空。** 宁可阻断确认，也不给一个看起来合理的假项目号。
- **阶段推进全手动。** 开工、已交 PM、已提交客户、客户验收四步各是各的，工作台只提示「可以开工了」，
  绝不替 PM 改状态。推进**只写实际发生的日期**，不碰计划和基准——让它顺手改一下计划，
  「实际 vs 计划」的偏差就永远是 0，整页分析立刻失去意义。
- **下一阶段要等前一阶段客户验收**，不是等它交给 PM。中间那段客户等待会把后续全部顺延，
  档期上看得见——客户拖的时间不该被藏起来。动不了时不给一个点了没反应的按钮，
  而是**只说该做的那一步为什么做不了**（把四个动作的前置全列出来是在背状态机，不是在回答问题）。
- **批准不等于开工，客户确认才算接项目。** 复核通过只是公司内部认了；报给客户、
  客户回话、PM 发开工通知，三步各是各的。走完前三步排期依然一个字节都没动。
- **客户不接受是终止，不是退回重报。** 而且必须写清是价格、排期还是范围——下次报价要用。
  这也是 `Rejected` 唯一的入口（它以前在类型里存在却永远到不了）。
- **能点的按钮一定做得成。** 凡是确认时会抛错的原因，都要在按钮上先说出来并禁用——
  「能点、点了什么都不发生」比禁用更糟。
- **同人兼两角只确认一次。** 待办按人合并，审计按角色展开——让同一个人点两次不会让审批更严格。
- **原报价永不覆盖。** 每次改动是新版本，旧版本原样留档；结项出账时汇总首次报价与全部已开工的变更。
- **每个非终态都有出路。** `availableActions` 是流转断点的守卫：任何一个还没走完的状态若没有可用动作，
  测试会当场失败。这条是 C8 验收时发现「总监报价中」没有录入入口后补的。
- **结项门禁串行，不能跳步。** 第 N 道只在第 1..N-1 道都完成后开放；第一道由阶段状态推导，不给手工打勾。
- **聊天截图不是正式证据。** 客户确认、IT 回执和出账通知只认正式邮件——出账时要拿得出来。
- **工作台不搬文件。** 只登记路径索引；剪切、备份和权限处理由 IT 用自己的权限执行。
- **路径只挂批次，不挂阶段。** 一个批次几十个资产，逐资产登记只会让表没法看。
- **路径只有一份。** 结项中心的最终包与归档路径直接读文件与归档的登记表，不另存一套。
- **不给打不开的链接。** 浏览器不允许网页打开本机路径，所以给的是一键复制，并写明为什么。
- **阻断理由不许引用切片进度。** 十个模块都做完了还拿「某某切片未交付」当借口，就是没跟上自己的实现；
  有测试扫过全部种子候选。
- **界面不出现内部类型名。** `QuoteCase` / `FeedbackBatch` 是给写代码的人看的，PM 看到的是「报价案件」。
- **分析不产生新数据。** 每个数字都是正式记录的投影，算不出来就不显示，绝不为了图表好看凑一个。
- **采纳不等于替你做了。** 处置记录的是 PM 的态度；报价模板、排期和通知一个字节都不会被那次点击改动，有测试逐个集合比对。
- **搜不到就是搜不到。** 全局搜索不做模糊补全——PM 拿着编号来搜，给他一个别的编号比给空结果更坏。
- **搜索不按人名建索引。** 技术上做得到，但那样它就成了「查某某人手上有什么活」的入口。
- **禁用必须说明原因。** 全站禁用控件都要带 title，有 E2E 逐个路由扫；这条替代了原来盯某一个按钮的测试。
- **不统计个人绩效。** 统计只到制作组 / 项目 / 资产 / 阶段；输出结构里根本没有人名字段，有测试守着。
- **前端拿不到完整 Key。** `LlmProvider` 类型上根本没有 `apiKey` 字段——不是「记得不要存」，是存不进来。
  有 E2E 提交真 Key 之后在整个 `localStorage` 里搜，搜不到才算过。
- **没接入的就说没接入。** 连接器逐条标审批门槛并给替代路径；页面上不出现「即将支持」。

## 本地运行

```powershell
cd apps/gamepmer-web
npm.cmd install
npm.cmd run dev -- --host 127.0.0.1 --port 5180 --strictPort
```

打开 <http://127.0.0.1:5180/>。

两个环境上的坑：PowerShell 会优先解析 `D:\Node\npm.ps1` 并被执行策略挡住，所以用 `npm.cmd`；
Vite 默认只监听 IPv6 时本机连不上，所以显式绑 `127.0.0.1`。

## 质量门禁

```powershell
npm.cmd test          # 单元与组件测试
npm.cmd run lint      # TypeScript 类型检查
npm.cmd run build     # 生产构建
npm.cmd run test:e2e  # Playwright 端到端（含三档视觉与键盘可达性）
```

E2E 会自动拉起 dev server（端口 5180），已在跑则复用。

## 已知限制

- **返修闭环还没接完。** 反馈项的「已重提」和「已关闭」两个状态在类型和界面标签里都有，
  但还没有动作能把反馈项推到那两个状态——范围内返修目前只到重排草案确认为止。

- **没有后端。** 数据存在浏览器 localStorage，通过 Repository 接口隔离；
  换成内网 API 时接口要改成异步并补加载态，这是已知的迁移成本。
- **没有账号、权限与审计存储。** 审计事件生成了，但没有多用户与访问控制。
- **没有连接器。** 邮件、企微、飞书都未接入——这不是没做完，是企业管理员审批拿不到。
  候选收件箱因此先做实四条零审批路径（粘贴、截图文字、路径、手工），接口到位只需加一个 Adapter。
- **字段提取是规则式的。** `domain/inbox.ts` 里是正则与关键词匹配，不是真实 LLM 调用；
  接口一致（每个字段带置信度和原文片段），换成模型抽取时 UI 不用改。
- **Demo 时钟锁定 2026-07-27。** 不锁的话种子数据会随真实日期漂移，验收截图无法复现。
- **LLM 没有真实调用。** 供应商预设、用途分档和脱敏开关都配好了，但没有内网网关，
  页面上的 AI 结果全部来自种子数据；Key 一旦填入即视为生产配置，应由管理员在正式内网环境操作。
- **一键跳转只能复制。** 浏览器不允许从 http 页面打开 UNC 路径，真跳转需要内网分发自定义协议助手。
- **仅桌面宽度。** 最低有效宽度 1280px，未做移动端适配。

上面这份限制清单在设置中心「数据与运维」里逐条渲染（`domain/settings.ts` 的 `KNOWN_LIMITS`），
改一处两处同时变——页面说「都做完了」而实际没做，比没有这一栏更糟。
