# GamePMer

面向游戏美术 PM 的**公司内网 Web 工作台**。

当前交付两条可验收的纵向闭环：

1. **候选收件箱**：外部消息 → AI 识别 → PM 核验 → 确认后才生成正式记录
2. **反馈重排**：客户反馈 → 范围分流 → 排期重排 → PM 确认 → 修订与通知草稿
3. **报价与变更**：追加需求 → 总监报价（含排期）→ 组长兼 BD 一次复核 → PM 发出开工邮件 → 资产解冻、排期更新

所有项目、客户、资产和消息均为虚构演示数据。工作台**不接入**真实邮件、企业微信、飞书或文件盘，
也不执行任何真实的对外操作——这是当前阶段的刻意边界，不是尚未接好的接口。

## 已实现的页面

| 页面 | 状态 | 说明 |
|---|---|---|
| 任务管理（首页） | 可用 | 待办由正式业务状态投影生成，每条都能追溯到项目、资产、阶段或反馈 |
| 项目总览与甘特 | 可用 | 按资产分组展开到每个可验收阶段，基准/当前/实际/等待客户四层日期同屏可比 |
| 排期管理与团队档期 | 可用 | 跨项目组合排期、制作组周容量、节点清单、批量计划录入与冲突检查 |
| 反馈中心 | 可用 | 反馈拆成资产级项、范围分流、重排草案、确认事务与通知草稿 |
| 候选收件箱 | 可用 | 零审批导入、逐字段置信度、阻断说明、确认事务生成正式记录 |
| 报价与变更 | 可用 | 版本化报价、双角色合并复核、开工门禁、只冻结受影响资产 |
| 结项中心 / 文件与归档 / 智能分析 / 设置中心 | 未实现 | 导航可点，页面如实说明在哪个切片交付 |

## 五分钟演示脚本

从「恢复示例数据」开始，这条路径有 E2E 用例逐步守着（`e2e/demo-script.spec.ts`）：

1. 首页看到 4 个项目、9 个资产、32 个阶段，以及 `P-3D-024` 的三条待分流客户反馈
2. 点开任一反馈，右侧显示原始邮件与批注截图路径、AI 判断依据（标明**建议未执行**）
3. 项目甘特里 `MECH-01` 六个 PBR 阶段各自成行，周末与公司休息日有底纹，今天线在 7/27
4. 排期管理看 3D 角色 A 组本周 `7 / 7.5` 人天；8/3 当周因 8/5 是休息日，可用人天降到 6
5. 反馈中心把「缩小肩甲比例」判为范围内 → 生成草案：受影响阶段顺延，LOD 跨过休息日排到 8/10
6. 微调草案，后续阶段自动顺延；甘特上草案是独立的斜纹层
7. **取消草案 → 正式计划零变化**
8. 重新生成并确认 → 写入修订 v1、基准保留、生成两封**未发出**通知草稿
9. 刷新浏览器，修订仍在
10. 把另一项判为范围外 → 创建变更单 `CQ-004`，只冻结受影响资产
11. 「恢复示例数据」回到相同初始状态

候选收件箱另有一条闭环（`e2e/inbox.spec.ts`）：

1. 打开候选收件箱看到 10 条候选，覆盖客户反馈 / 阶段完成 / 报价需求 / IT 回执四种类型
2. 每个字段各自带置信度和原文片段——不是一个笼统的百分比
3. 「需补全」里那条缺关联资产的：确认键禁用，右侧写明**缺哪个字段**
4. OCR 那条把 `0` 认成了 `O`，项目号置信度 42%，有值也照样阻断
5. 报价需求那条诚实阻断：「报价与变更在切片 5 交付」，不给一个点了没反应的键
6. 补上关联资产 → 字段标记「PM 填写」→ 确认键解禁
7. 确认 → 生成反馈批次 `F-018`，右侧能一路点到反馈中心
8. **忽略候选不改任何正式数据**，而且能退回待确认
9. 粘贴一段带 `【P-3D-031】PROP-02` 的文本 → 自动提取项目、资产、阶段
10. 贴一段没有项目号的文本 → 字段留空并阻断，**不编造项目号**
11. 同一段原文导入两次 → 自动判重，待确认数量不变

报价与变更的第三条闭环（`e2e/quotation.spec.ts`）：

1. `CQ-004` 追加报价展开到每个阶段，各有人天、单价和节点——不是一个总金额
2. 待复核清单里 `CQ-004` **只有一条**，但「组长」「BD」两个角色都写出来，并标注「合并为 1 次确认」
3. 复核通过 → 甘特上 `MECH-01` 烘焙仍标「等待变更报价」：**批准不等于开工**
4. 发出变更开工邮件（人工声明）→ 资产解冻、排期按报价单更新、基准不动
5. 未受影响的 `MECH-02` 从头到尾没被这次变更动过
6. 应结汇总 = 首次报价 `Q-021` ¥42,000 + 追加 `CQ-004` ¥9,000，原报价版本没被改写
7. `Q-029` 的项目还没建出来 → 开工被诚实阻断，按钮禁用并说明缺什么
8. `Q-030` 还在「总监报价中」→ 用「录入总监报价」按阶段模板生成行、填人天与节点 → 提交进入待复核
9. 「退回总监修改」不是死胡同：以上一版为底稿重新提交，生成 v2 且 v1 原样留档

## 几条不会让步的规则

这些规则都有测试守着，不是文档里的口号：

- **基准不可覆盖。** 所有修订只动当前计划，基准日期从头到尾没被写过。
- **草案不碰正式数据。** 生成、微调、预览全程不改 `StagePlan`，取消就是把草案丢掉。
- **确认是原子操作。** 有阻断时整体拒绝，绝不出现「部分阶段已改、部分没改」。
- **工作台不发信。** 通知只到草稿；真实发送由 PM 在 Outlook 或企微完成，回来标记。
  标记记录的是人工声明，不是系统投递回执。
- **AI 只建议。** 范围判定、排期修改、通知发送都要 PM 动手，界面上写明「建议未执行」。
- **容量按全量算。** 筛选只决定显示哪几行，不影响制作组档期数字——
  否则筛掉几个项目就会显示出不存在的空闲。
- **不留假控件。** 每个按钮要么真做事，要么禁用并说明在哪个切片交付。
- **候选不是正式记录。** 确认之前，项目、排期、反馈和结项的数据一个字节都不会变。
- **识别不出来就留空。** 宁可阻断确认，也不给一个看起来合理的假项目号。
- **批准不等于开工。** 复核通过时排期一个字节都没变，PM 发出开工邮件才生效。
- **同人兼两角只确认一次。** 待办按人合并，审计按角色展开——让同一个人点两次不会让审批更严格。
- **原报价永不覆盖。** 每次改动是新版本，旧版本原样留档；结项出账时汇总首次报价与全部已开工的变更。
- **每个非终态都有出路。** `availableActions` 是流转断点的守卫：任何一个还没走完的状态若没有可用动作，
  测试会当场失败。这条是 C8 验收时发现「总监报价中」没有录入入口后补的。

## 本地运行

```powershell
cd apps/gamepmer-web
npm.cmd install
npm.cmd run dev -- --host 127.0.0.1 --port 5180 --strictPort
```

打开 <http://127.0.0.1:5180/>。

两个环境上的坑：PowerShell 会优先解析 `D:\Node\npm.ps1` 并被执行策略挡住，所以用 `npm.cmd`；
Vite 默认只监听 IPv6 时本机连不上，所以显式绑 `127.0.0.1`。

## 质量门禁

```powershell
npm.cmd test          # 单元与组件测试
npm.cmd run lint      # TypeScript 类型检查
npm.cmd run build     # 生产构建
npm.cmd run test:e2e  # Playwright 端到端（含三档视觉与键盘可达性）
```

E2E 会自动拉起 dev server（端口 5180），已在跑则复用。

## 已知限制

- **没有后端。** 数据存在浏览器 localStorage，通过 Repository 接口隔离；
  换成内网 API 时接口要改成异步并补加载态，这是已知的迁移成本。
- **没有账号、权限与审计存储。** 审计事件生成了，但没有多用户与访问控制。
- **没有连接器。** 邮件、企微、飞书都未接入——这不是没做完，是企业管理员审批拿不到。
  候选收件箱因此先做实四条零审批路径（粘贴、截图文字、路径、手工），接口到位只需加一个 Adapter。
- **字段提取是规则式的。** `domain/inbox.ts` 里是正则与关键词匹配，不是真实 LLM 调用；
  接口一致（每个字段带置信度和原文片段），换成模型抽取时 UI 不用改。
- **Demo 时钟锁定 2026-07-27。** 不锁的话种子数据会随真实日期漂移，验收截图无法复现。
- **仅桌面宽度。** 最低有效宽度 1280px，未做移动端适配。
